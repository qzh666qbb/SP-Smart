# 小程序排课与体测管理系统数据库设计文档

## 1. 文档信息

| 项目   | 内容                   |
| ---- | -------------------- |
| 系统名称 | 小程序排课与体测管理系统         |
| 数据库  | MySQL 8.0            |
| 字符集  | utf8mb4              |
| 排序规则 | utf8mb4_0900_ai_ci   |
| 时间类型 | datetime             |
| 主键类型 | bigint unsigned      |
| 删除策略 | 业务数据原则上采用软删除         |
| 权限角色 | ADMIN、TEACHER、PARENT |

---

# 2. 数据库设计目标

数据库需要支撑以下核心业务：

1. 管理员、教师和家长账号登录。
2. 家长与多个学员绑定。
3. 学员、教师、课程和班级管理。
4. 单次排课、周期排课和班级排课。
5. 学员签到、请假、缺勤和课程完成。
6. 自动扣减课时、人工充值和课时修正。
7. 动态配置体测模板和指标。
8. 单个录入及 Excel 批量导入体测数据。
9. 自动生成 PDF 或图片体测报告。
10. Excel 导入导出任务管理。
11. 管理员和教师操作审计。

---

# 3. 核心设计原则

## 3.1 权限不使用复杂 RBAC

第一版角色固定，不设计以下表：

```text
role
permission
role_permission
user_role
```

用户角色直接保存在用户表中：

```text
ADMIN
TEACHER
PARENT
```

接口层根据角色进行鉴权。

管理员和教师共享主要业务接口：

```text
课程管理
班级管理
排课管理
课程执行
课时管理
体测模板
体测数据
体测报告
Excel 导入导出
```

管理员额外拥有：

```text
教师账号管理
家长账号管理
全部操作日志查询
```

---

## 3.2 周期排课和实际课程分离

系统不能只保存“每周六上课”这一条规则。

应区分：

```text
schedule_series
周期排课规则

lesson
实际生成的每一节课
```

例如：

```text
schedule_series：
每周六 10:00 上课，共12周

lesson：
2026-07-25 10:00
2026-08-01 10:00
2026-08-08 10:00
……
```

这样才能独立处理某次课程的调课、请假、取消和课时扣减。

---

## 3.3 课程和学员上课状态分离

一节班级课可能包含多个学员，不同学员的状态可能不同：

```text
张小明：到课
李小红：请假
王小刚：缺勤
```

因此需要：

```text
lesson
课程实例

lesson_student
每个学员在该课程中的状态
```

不能只在 `lesson` 表中保存统一签到状态。

---

## 3.4 课时采用账户和流水模式

课时系统由两部分组成：

```text
student_hour_account
当前课时账户余额

hour_transaction
每次课时变动流水
```

课时余额禁止由前端直接修改。

任何充值、扣减、退回和调整，都必须先生成流水，再更新账户余额。

---

## 3.5 体测指标采用动态结构

不能把身高、体重、肺活量等直接设计成固定字段：

```text
height
weight
lung_capacity
jump_distance
```

否则新增指标时必须修改数据库结构。

应使用：

```text
physical_template_item
定义指标

physical_record_value
保存指标值
```

# 6. 通用字段规范

除关系表外，主要业务表建议统一包含以下字段：

| 字段         | 类型              | 说明              |
| ---------- | --------------- | --------------- |
| id         | bigint unsigned | 主键              |
| created_by | bigint unsigned | 创建人用户 ID        |
| created_at | datetime        | 创建时间            |
| updated_by | bigint unsigned | 最后修改人用户 ID      |
| updated_at | datetime        | 最后修改时间          |
| deleted_at | datetime        | 软删除时间，未删除为 NULL |
| version    | int unsigned    | 乐观锁版本号          |

`created_by` 和 `updated_by` 关联 `sys_user.id`。

高频业务表建议增加 `version`，避免多个教师同时修改课程或课时账户时发生覆盖。

# 7. 用户和基础资料表

## 7.1 用户表 `sys_user`

保存管理员、教师和家长的登录账号。

| 字段                  | 类型              | 必填 | 说明                      |
| ------------------- | --------------- | -: | ----------------------- |
| id                  | bigint unsigned |  是 | 主键                      |
| username            | varchar(64)     |  否 | 用户名，管理员 PC 登录使用         |
| password_hash       | varchar(255)    |  否 | 密码哈希                    |
| role                | varchar(20)     |  是 | ADMIN、TEACHER、PARENT    |
| phone               | varchar(20)     |  否 | 手机号                     |
| wechat_openid       | varchar(128)    |  否 | 微信小程序 OpenID            |
| wechat_unionid      | varchar(128)    |  否 | 微信 UnionID              |
| status              | varchar(20)     |  是 | ENABLED、DISABLED、LOCKED |
| last_login_at       | datetime        |  否 | 最后登录时间                  |
| password_updated_at | datetime        |  否 | 密码更新时间                  |
| created_at          | datetime        |  是 | 创建时间                    |
| updated_at          | datetime        |  是 | 更新时间                    |
| deleted_at          | datetime        |  否 | 软删除时间                   |

### 索引和约束

```text
UNIQUE(username)
UNIQUE(wechat_openid)
INDEX(phone)
INDEX(role, status)
```

手机号不建议强制唯一，因为实际业务中可能存在：

* 同一个手机号绑定多个孩子；
* 家长和教师使用相同联系方式；
* 历史数据缺失或重复。

业务登录绑定时，应根据角色和绑定关系进行校验。

# 8. 课程和班级表

## 8.1 课程表 `course`

课程表保存课程定义，不代表某一天具体发生的课程。

| 字段                       | 类型              | 必填 | 说明                           |

| course_name              | varchar(100)    |  是 | 课程名称                         |
| course_type              | varchar(20)     |  是 | ONE_TO_ONE、SMALL_CLASS、GROUP |
| default_duration_minutes | int unsigned    |  是 | 默认时长                         |
| default_consume_hours    | decimal(8,2)    |  是 | 默认消耗课时                       |

| deleted_at               | datetime        |  否 | 软删除时间                        |

```text
UNIQUE(course_code)
```

# 9. 排课表

| start_date      | date            |  是 | 计划开始日期              |
| end_date        | date            |  否 | 计划结束日期              |
| start_time      | time            |  是 | 开始时间                |
| end_time        | time            |  是 | 结束时间                |
| consume_hours   | decimal(8,2)    |  是 | 默认消耗课时              |
| status          | varchar(20)     |  是 | ACTIVE、PAUSED、ENDED |
| created_by      | bigint unsigned |  是 | 创建人                 |
| created_at      | datetime        |  是 | 创建时间                |
| updated_by      | bigint unsigned |  是 | 修改人                 |

### 冲突检查

创建或修改课程时，应检查：

```text
同一教师的时间冲突
同一学员的时间冲突
开始时间必须早于结束时间
取消课程不能再次完成
已完成课程修改需要特殊确认
```

### 课程扣课幂等规则

完成课程时可生成：

```text
idempotency_key =
LESSON_CONSUME:{lesson_student_id}
```

撤销扣课时：

```text
idempotency_key =
LESSON_ROLLBACK:{lesson_student_id}
```

这样即使教师重复点击“完成课程”，后端也不会重复扣课。

### 禁止操作

不得：

```text
DELETE FROM hour_transaction
```

错误流水只能通过 `ROLLBACK` 类型反向冲正。

# 18. 核心事务设计

## 18.1 完成课程并扣课时

一次“完成课程”操作必须在同一个数据库事务中完成：

```text
1. 锁定 lesson_student
2. 判断是否已经扣课
3. 锁定 student_hour_account
4. 检查剩余课时
5. 写入 hour_transaction
6. 更新 student_hour_account
7. 更新 lesson_student.hour_transaction_id
8. 更新 lesson_student 到课状态
9. 判断全部学员是否处理完成
10. 更新 lesson.status
11. 提交事务
```

伪逻辑：

```text
BEGIN

SELECT account
FOR UPDATE

检查 idempotency_key 是否存在

INSERT hour_transaction

UPDATE student_hour_account
SET remaining_hours = remaining_hours - consume_hours,
    version = version + 1

UPDATE lesson_student
SET hour_transaction_id = transaction_id

COMMIT
```

---

## 18.2 撤销已完成课程

不允许删除原消费流水。

撤销流程：

```text
1. 查询原 CONSUME 流水
2. 检查是否已经生成 ROLLBACK
3. 新增正向 ROLLBACK 流水
4. 恢复课时余额
5. 清除或标记课程扣课关系
6. 更新课程状态
```

# 19. 外键策略

建议核心关系使用外键，但删除规则统一采用限制删除：

```text
ON DELETE RESTRICT
ON UPDATE RESTRICT
```

不建议使用：

```text
ON DELETE CASCADE
```

例如，删除课程时不能自动删除历史上课记录和课时流水。

对于日志、导入任务等弱关联数据，可以只建立普通索引，不强制外键，以避免历史数据被业务删除影响。

# 22. 数据权限校验规则

数据库保存关系，具体权限由后端服务层校验。

## 管理员

```text
可以访问全部业务数据
可以管理教师和家长账号
可以查询全部操作日志
```

## 教师

```text
可以管理课程
可以管理班级
可以进行排课和调课
可以调整课时
可以管理体测数据和报告
可以进行 Excel 导入导出
不能创建或删除管理员账号
默认不能查看其他用户密码或登录凭证
只能查看本人操作日志
```

## 家长

家长访问任意学员数据前，必须满足：

```text
parent_student_relation.parent_id = 当前家长
AND
parent_student_relation.student_id = 目标学员
AND
bind_status = CONFIRMED
```

前端隐藏页面不能代替后端数据权限校验。
